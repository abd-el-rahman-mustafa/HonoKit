# Contributing to HonoKit

Thank you for helping. Bug reports, ideas, translations and pull requests are all welcome.

## Issues

- **A problem:** use **Report a problem** in the app (Settings › About), which fills in the version
  and system for you, or open a [bug report](https://github.com/abd-el-rahman-mustafa/HonoKit/issues/new?template=bug_report.yml).
  Attach a file only if it has nothing private in it: issues are public.
- **An idea:** open a [feature request](https://github.com/abd-el-rahman-mustafa/HonoKit/issues/new?template=feature_request.yml).
- **A security problem:** never in a public issue; see [SECURITY.md](SECURITY.md).

English and Arabic are both fine.

## Pull requests

1. **Fork** the repository and clone your fork.
2. Create a **branch** for one change: `git switch -c fix-arabic-search`.
3. Make the change, with tests (below).
4. Check it:
   ```bash
   npm run typecheck
   npm test
   ```
   For anything you can see, also run `npm run smoke` (builds the app, drives it in English and
   in Arabic with a dark theme, and saves screenshots in `smoke-out/`) and look at the screenshots.
5. Push the branch to your fork and open a **pull request** against `main`. Say what it changes
   and why; link the issue if there is one.

For a large change, open an issue first so we can agree on the approach before you spend time on it.

## Setting up

Node.js 20 or later and Windows 10/11 (the app also builds on macOS and Linux, but Windows is what
it is tested on).

```bash
npm ci
npm run dev        # the app with hot reload
```

## How the code is laid out

| Folder | What |
| --- | --- |
| `src/engine/` | Everything that reads and changes PDFs and pictures (MuPDF, pdf-lib, sharp, ONNX). No Electron. |
| `src/ops/` | Each tool as an operation: input checked, PDF in, PDF out. |
| `src/worker/` | The process that runs the engine, so the window never freezes. |
| `src/main/` | Electron's main process: windows, files, dialogs, updates. Every call from the window is checked again here. |
| `src/preload/` | The only bridge between the window and the main process. |
| `src/renderer/` | The interface (React). Every string in English and Arabic in `src/renderer/src/i18n.ts`. |
| `src/shared/` | Types and pure functions used on both sides. |
| `test/` | Vitest. Every test document is generated by the tests themselves. |
| `resources/` | Fonts, OCR and image AI models, spelling dictionaries shipped with the app. |

## Code style

- TypeScript, strict. Two spaces, single quotes, no semicolons; follow the file you are in.
- Comments say **why**, in plain sentences; the code says what.
- Every user-facing string goes in `i18n.ts`, in **both** English and Arabic. Check the layout
  right to left (the smoke run's `ar-dark` screenshots).
- Nothing may go online without the person asking. No telemetry, no accounts.
- Tests make their own files. Never commit real documents, newspapers or anything personal.
  To try your own files locally, point the tests at them with environment variables
  (`POWERPDF_TEST_PDFS="a.pdf;b.pdf" npx vitest run test/external.test.ts`) or put them in
  `corpus/`, which git ignores.
- A few things are fragile and covered by tests: do not upgrade `mupdf` without running the
  ligature tests in `test/text.test.ts`, and do not change the bundled Arabic font without the
  rendering tests.
